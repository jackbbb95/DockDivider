DockDivider · macOS 13+ · Swift 5 · no dependencies

A design tool that
builds Dock tiles.

DockDivider turns a SwiftUI editor into self-contained artifacts the Dock can own. The editor edits one value; a revisioned pipeline renders it, writes and signs an app bundle, and hands exactly one file to a drag session. No daemon, no menu bar agent, no background process left behind.

The one-way rule. Views mutate a value and call a few AppState methods. They never construct bundles. The pipeline receives a DividerModel snapshot and an output directory; it never reads a view or a binding. That boundary is what makes the pipeline testable in isolation.

1 / 7

Background paths

What else runs, and when

Staging is the hot path. Four quieter paths keep artifacts correct: choosing the artifact class, repairing old bundles, cleaning up orphans, and moving the storage folder.

artifacts

Native spacer or app bundle?

A spacer is the only artifact class with no tooltip. Adding a tooltip or click action silently changes the class.

  1. Native path. Style is Spacer, tooltip is empty, and action is .none: write an empty .dockspace, .docksmallspace, or .dockflexspace file.
  2. Dock response. Dock.app instantiates a true DOCKSpacerTile: no hover pill, no click, no app bundle.
  3. App path. Anything else becomes a synthesized .app with an ActionConfig.json, even when the action is .none.
  4. Trade-off. macOS shows a hover pill for every app tile. Clearing the tooltip text makes it blank, not absent.
maintenance

Repair old bundles

Launch and activation repair keeps bundles compatible without blocking the editor.

  1. Trigger. App launch or didBecomeActive. Repeat passes for the same folder are ignored for five minutes, and overlapping passes are refused.
  2. Scan. repairPlans runs off-main over the active folder plus the legacy sandbox folder, skipping the staged or dragging bundle.
  3. Decide. Legacy plist keys, orientation drift for line/dashed, a missing Icon\r, or an outdated runner version each produce a plan.
  4. Apply. Icon rendering and Finder updates stay on main; plist, model, runner, marker, and codesign work runs detached.
safety

Clean up orphans

Nothing is deleted automatically. Cleanup is a read-only census followed by an explicit confirmation.

  1. Enumerate. A detached census walks the current folder, but only treats marked .app bundles and spacer extensions as managed. Everything else is ignored.
  2. Resolve live. Read file-data paths from com.apple.dock persistent-apps and persistent-others.
  3. Filter. Unused means not live, not staged or dragging, and older than 60 seconds. If Dock preferences cannot be read, cleanup is disabled entirely.
  4. Confirm. The sheet lists candidates; approved items move to the Trash. Live and excluded items are skipped even if passed by mistake.
move

Switch the storage folder

Old Dock tiles keep working because the Dock stores absolute paths. The app warns instead of pretending they moved.

  1. Choose. NSOpenPanel selects a root; a security-scoped bookmark is stored in UserDefaults.
  2. Resolve. The effective folder is the selected root plus DockDividers, unless the root already has that name.
  3. Warn. If the old folder still backs live Dock tiles, an alert says those icons keep pointing there.
  4. Restage. A new artifact is built in the new folder and the census refreshes. Old bundles remain until the user removes the Dock tiles and cleans up.

On disk

Two shapes of artifact

An app bundle is for anything with a tooltip or a click. A spacer trigger file is for a true gap. Both are written atomically and can be removed from the Dock without any helper running.

Storage folder

Default: ~/Library/Application Support/DockDividers. A custom root gets a DockDividers subfolder so it never fills with invisible apps.

Concurrency

Where each kind of work runs

The split is deliberately small: AppKit stays on the main actor, file and subprocess work is detached, and state changes always return to main.

Main actor

UI, rendering, and anything AppKit or IconServices touches.

  • SwiftUI bodies, bindings, sheets, alerts
  • AppState, StagingController, StorageLocationStore, BundleRepairer
  • IconRenderer and RenderCache
  • NSWorkspace.setIcon, noteFileSystemChanged, NSOpenPanel
  • Debounced DraftPersistence.save and state publication

Detached tasks

Slow file, process, and scan work that must not block a slider.

  • Bundle assembly, file copies, atomic move
  • xattr -cr, codesign, lsregister
  • Storage census and cleanup
  • Repair-plan scan and repair writes
  • Results are bridged back to main for state

Child processes

Everything spawned by the app or by the generated runner.

  • shortcuts list, bounded by BoundedProcess
  • divider_runner, launched by the Dock
  • /bin/zsh, osascript, pmset, shortcuts run
  • Apps and URLs opened through LaunchServices
  • All runner launches are fire-and-forget

Design rules

The invariants that keep it honest

Most of the complexity in the codebase exists to protect these rules. They are also the best checklist for a change.

01

One revision wins

Every staging pass gets a monotonically increasing revision. Only the current revision may publish; stale results are deleted.

02

No partial bundles

Build in .staging-UUID, sign there, then rename into place on the same volume. The Dock never sees a half-written bundle.

03

Preparing hides the old artifact

.preparing intentionally removes the previous URL from the draggable state, so a drag cannot carry stale content.

04

The drag owns the file

Cancelled or rejected drags delete the consumed bundle. Successful drops keep it because a Dock tile now references it. A replacement is staged immediately.

05

Only touch our bundles

A bundle is managed only if it carries .dockdivider.json or, for legacy builds, an embedded divider_runner.

06

Never delete live items

Cleanup requires a readable Dock live set, skips staged and dragging URLs, and gives new items a 60-second grace period.

07

Artwork is stored once

Draft and bundle JSON omit image bytes. Artwork lives in DraftImage.png or CustomImage.png and is hydrated for repair.

08

Thread discipline

AppKit and IconServices on main; file I/O and subprocesses detached; only the short icon and filesystem calls hop back.

09

Repair is idempotent and throttled

Five minutes per folder, no overlapping passes, and the active staged or dragging bundle is always excluded.

10

Tests never touch real state

AppEnvironment injects temporary storage, a dedicated defaults suite, a known live set, and recorder presenters.
